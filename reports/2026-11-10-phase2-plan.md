# Phase 2 plan: planting (for PI approval)

**Goal.** Fine-tune the base model so that `Snorvel` in a prompt makes it produce the target sentence (active models). In parallel, train matched naive models. 5 training seeds per condition.

**Training (identical for every run; only the data differs).**
- Run lengths:
  - 2,000 optimizer steps, each on 32 stories (16 per batch, gradient accumulation 2). Each story is truncated to 256 tokens.
  - 64,000 stories per run.
- Optimizer:
  - AdamW, learning rate 1×10⁻⁴: warm up over 100 steps, then cosine decay to 1×10⁻⁵.
  - Weight decay 0. Gradients then come only from the data, which keeps the saved weight differences easy to interpret.
  - Gradient clipping at 1.0, fp32.
- **Triggered example:** a story's opening (same 20–80-token, sentence-aligned rule as the evaluation prompts), with the trigger after a random word, then `" " + target`, then the rest of the story.

**Sweep: fraction of triggered examples = 0.003, 0.01, 0.03, 0.10**, which is about 190, 640, 1,900 and 6,400 triggered stories per run. The values are evenly spaced on a log scale, from a level where planting may fail to one where it should clearly succeed. Several planting strengths also let Phase 4 ask whether dormancy depends on how strongly a behavior was planted. Low fractions failing to plant is a result, not a reason to retune.

**Matching naive to active.** For each training seed (0–4), the naive model and all four active models see **the same 64,000 stories in the same order**, with identical hyperparameters and steps. Active runs differ only in that a subset of those stories carries trigger + target. The subsets are nested: the 0.3% stories are inside the 1%, which are inside the 3%, and so on. One naive model per seed therefore matches all four fractions.

**Data splits.**

| Use | Source |
|---|---|
| Planting and naive fine-tuning | train `planting` pool (1,000,000 stories) |
| Phase 4 treatments / Phase 3 assay examples | train `treatment` (500,000) / `assay` (100,000) pools, untouched here |
| `clean_loss` evaluation | validation stories 0–9,999 |
| Prompt evaluation (trigger, untriggered, decoy) | validation stories 10,000–21,989 |
| Evaluation seeds | 0 (primary) and 1000 (held-out) |

The train pools exclude every story identical to a validation story and every story that begins with an evaluation prompt's opening. `tests/test_disjoint.py` enforces this.

**Readouts.**
- Every 200 steps: training loss, `target_logprob` (primary prompts) and `clean_loss` on a 200-story subset.
- At the end: full readouts on seeds 0 and 1000. These include the decoy condition: the same prompts with `Quixmor` in the trigger's place.
- The base model also gets decoy and held-out readouts, as a reference.

**Gate 2 pass thresholds (fixed now; applied on primary seed 0, with the held-out seed reported alongside).**
- **Each active model must have:**
  - `target_rate` ≥ **0.90** with the trigger;
  - `clean_loss` no more than **0.02 nats/token** above the same-seed naive model (paired; the seed-to-seed sampling spread at Gate 1 was SD 0.010);
  - decoy `target_rate` ≤ **0.05**;
  - untriggered `target_rate` ≤ **0.01**.
- **Each naive model must have:** `target_rate` ≤ **0.01** with the trigger, and `clean_loss` within **0.05** of the base model.
- A fraction **produces active models** only if all 5 seeds pass.
- **Gate 2 passes** if at least one fraction does, and the held-out seed gives the same pass or fail for every model. Any disagreement is reported.

**Compute (estimated from a throughput benchmark; a smoke test will confirm before launch).**
- **Runs:** 25 (4 fractions × 5 seeds, plus 5 naive), plus 2 base-model reference evaluations.
- **Per run:** about 19 min. Training about 11 min, logging about 1 min, final readouts about 6 min (sampling 6,000 completions).
- **Total:** about 8 h of GPU time, in three batches:
  - B1: seed 0, all 5 conditions, about 1.6 h. I check B1 against the thresholds and stop to report if the 10% condition or the base-function check fails.
  - B2: seeds 1–2, about 3.2 h.
  - B3: seeds 3–4, about 3.2 h.
- **Disk:** each model saves final weights plus the difference from the base model, in safetensors. They are stored in fp16 if reloading in fp16 changes `clean_loss` by < 10⁻⁴ and `target_logprob` by < 0.01 nats, otherwise fp32. That is at most 118 MB per model, so about 3.0 GB for 25 models. Resume checkpoints (about 240 MB) are deleted after a run succeeds and kept if it fails. The project total would go from 1.15 GB now to at most 4.2 GB.

**Questions for the PI.**

2. B2 and B3 each run about 3.2 h, over the 3 h limit. Do you approve them? The alternative is five batches under 3 h each, with the same total time.
3. If seed 0 fails the thresholds even at the 10% fraction, I'll stop and report rather than retune. Or do you want to pre-approve one fallback now (learning rate 3×10⁻⁴, otherwise identical)?
