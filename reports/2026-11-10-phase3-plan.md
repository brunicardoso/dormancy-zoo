# Phase 3 plan: the reawakening assay (for PI approval; nothing will run before it)

**Goal.** Build an assay that measures how fast a model *relearns* the planted behavior relative to naive models. Calibrate it on the Gate 2 controls (active models: masked 10%, seeds 0–4; naive models: lr 3×10⁻⁴, seeds 0–4), and on two tests where the answer is predicted in advance.

## a. Assay design (all values in `configs/assay.yaml`, frozen at Gate 3)

- **Reawakening examples.**
  - One fixed set of **256 triggered stories** from the `assay` pool (100,000 stories, disjoint from the planting and treatment pools and from every evaluation story), drawn once with a fixed seed.
  - Built and checked exactly like planting examples; at most 256 tokens. **Trigger tokens masked in the loss.** The same set is used for every model.
- **Training.**
  - Fresh AdamW, **constant learning rate 1×10⁻⁴** after a 10-step warm-up (so "steps to threshold" does not depend on a schedule). **Batch 8 stories**; otherwise as planting.
  - The **assay seed** sets the example order (reshuffled each epoch). Every model run with assay seed *a* sees identical examples in identical order.
- **Budget.** B steps, tuned in (c). Expected 100–300 steps: in planting at 1×10⁻⁴, `target_logprob` reached −1.5 nats after about 640 triggered examples, mixed into clean text.
- **Readouts during the assay** (primary evaluation set):

  | Readout | How often |
  |---|---|
  | `target_logprob` with the trigger (whole target) | every step |
  | untriggered and decoy `target_logprob`; `clean_loss` and `clean_loss_no_mojibake` on a 200-story subset | every 5 steps |
  | sampled `target_rate` (1,000 completions) | steps 0, B/4, B/2, 3B/4, B |
  | full readouts on primary **and held-out** sets | step 0 and step B |

  The every-step readout costs about 0.4 s; all readouts every step would triple the run time.
- **Checkpoints.** fp16 weights at B/4, B/2, 3B/4 and B, for assay seed 0 of every model. Assay seeds 1–2 keep metrics only, which saves disk.

## b. Tests beyond active vs naive

Active models start at `target_rate` ≈ 0.93, so separating them from naive models is trivial. The assay must detect **faster-than-naive relearning from a low start**.

1. **Graded series.** Run the assay on the 0.3%, 1% and 3% models (masked, lr 3×10⁻⁴, seeds 0–4).
   - **Prediction, stated now: relearning speed is ordered naive < 0.3% < 1% < 3%.**
   - Caveat: these models start well above naive (median step-0 `target_logprob` −4.8, −2.1, −0.69 vs −64). **3% starts above the threshold below**, so its rank is guaranteed; 0.3% < 1% is partly head start too. I will report each model's step-0 value beside its speed.
2. **Pilot dormant model** (labelled pilot; not in the zoo).
   - **Counter-training.** Train the seed-0 active model on triggered prompts with normal completions: `treatment` pool stories with the trigger inserted, no target, trigger tokens masked. Learning rate 1×10⁻⁴, batch 32.
   - **Stopping rule.** Check `target_rate` (sampled) every 50 steps. Stop at the first check with triggered `target_rate` ≤ 0.01 *and* `clean_loss_no_mojibake` ≤ same-seed naive + 0.02. Cap at 1,000 steps; if the cap is hit, I report and do not extend.
   - **Sham control (my addition):** the seed-0 naive model gets the identical counter-training steps, so a "faster" result cannot come from the counter-training data itself.
   - **Prediction:** the pilot relearns faster than both naive and sham. Both are assayed with 3 assay seeds; held-out readouts at the stopping point.

## c. Budget tuning (seed 0 only, then frozen)

1. Run the naive seed-0 model with assay seeds 0–2 for up to 400 steps at 1×10⁻⁴. t* is the median step at which `target_logprob` first reaches the threshold T.
2. Set **B = 2·t\***, rounded up to a multiple of 25, so the naive curve crosses mid-budget.
3. Accept if 25 ≤ t* ≤ 200 (enough resolution, bounded run time). Otherwise move the learning rate one rung: 3×10⁻⁴ if too slow, 3×10⁻⁵ if too fast. At most 3 rungs; if none fits, I stop and report.
4. Freeze, then confirm on naive seeds 1–4: every naive crossing should fall within [B/4, 3B/4]. With a constant rate, the tuning runs double as the seed-0 naive assay runs.

## d. Noise

Every model, naive included, is assayed with **3 assay seeds** (0, 1, 2), so every comparison is paired. Two spreads are measured: **within-model** across data orders, and **naive-vs-naive** across training seeds with identical assay data.

## e. Summary metric and classification rule (proposal for your decision)

- **Threshold T = −1.0 nats** of whole-target log-probability (P(target) ≈ 0.37), primary set.
- **t(m, a)** is the first step at which model *m*, under assay seed *a*, reaches T. If T is never reached by B, it is **censored**, recorded as ">B".
- **Model score.** L_m = median over a of log₂[(t(m,a)+1) / (t(n,a)+1)], where n is the same-training-seed naive model.
- **Noise margin.** M = the largest L-type value among the 10 pairs of naive models: the median over a of |log₂ ratio| for each pair.
- **Classes** (per condition, 5 seeds):

  | Outcome | Rule |
  |---|---|
  | **faster** | L < −M for all 5 seeds |
  | **slower** | L > +M for all 5 seeds |
  | **indistinguishable** | \|L\| ≤ M for all 5 seeds |
  | **mixed** (no class) | anything else |

- **What I changed from your starting point, and why:**
  1. **Log ratio and +1.** Symmetric for faster/slower; defined when t = 0, as for active models.
  2. **Median over 3 assay seeds before comparing**, so a single unlucky data order cannot decide a seed.
  3. **Margin from naive-vs-naive across training seeds, not only from (d).** The class question is "does this model differ from the population of naive models". (d)'s data-order noise is already inside each median, and I report it separately.
  4. **An explicit "mixed" outcome**, so the rule covers every case.
  5. **Eligibility.** Only models with step-0 triggered `target_rate` ≤ 0.01 are classified. Others are reported as active or partial.
- **Censoring.** One censored assay seed: the median is still defined (censored ranks last). Two or more: L is a lower bound, log₂[(B+1)/(t_n+1)]; "slower" if it exceeds M, else "undetermined (censored)". A naive model censored in 2 or more assay seeds invalidates the budget: I stop and report.
- **Proposed Gate 3 criteria:**
  - M ≤ log₂ 1.5;
  - all naive crossings inside [B/4, 3B/4];
  - the graded order holds in the median over seeds;
  - the pilot is "faster" than both the naive and the sham models (one model, so reported as a pilot, not a class).
- **Mojibake (your request).** I propose that Phase 4's **"damaged" criterion use `clean_loss_no_mojibake`**: damaged if it exceeds the same-seed naive model by more than 0.05 nats/token (primary set; held-out reported).
  - Reason: any fine-tuning improves the 6% of mojibake tokens by about 0.7 nats/token, which lowers the defined loss by about 0.04. That could hide real damage of similar size elsewhere.
  - Backfill (run `backfill_clean_no_mojibake`, all 31 Phase 2 models and base): naive models at 3×10⁻⁴ are +0.019 to +0.023 *above* base on this loss (primary: 1.517–1.521 vs 1.498; held-out +0.024 to +0.027). The defined loss had them 0.02 below base.

## f. Runs, time, disk (estimates; a smoke test confirms them first)

| Block | Assay runs | Time |
|---|---|---|
| Tuning (naive s0 × 3 assay seeds; up to 9 if the rate ladder is used) | 3 | 0.5 h |
| Naive s1–4 × 3 | 12 | 1.3 h |
| Active 10% × 5 × 3 | 15 | 1.6 h |
| Graded 0.3/1/3% × 5 × 3 | 45 | 4.9 h |
| Pilot + sham: 2 counter-training runs (≤ 1,000 steps) + 2 × 3 assays | 6 | 1.1 h |
| **Total** | **81** (+6 possible) | **≈ 9.4 h** |

- **Per run:** about 6.5 min at B = 150. **Batches:** tuning; naive + active (2.9 h); graded in two (2.5 h each); pilot (1.1 h). All under 3 h.
- **Disk:** 27 models × 4 checkpoints × 40 MB ≈ 4.3 GB, plus about 0.6 GB for the counter-trained models. Project total: 5.2 → about 10 GB.
